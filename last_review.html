Tasks

Fix http_get Reuse Bug

Must

Problemhttp_get() fails after http_client has already been set because the line uses A && B || C as if it were if/else logic.

Why it mattersWeather calls http_get twice. The second call can incorrectly return no http_get tool installed.

Suggested solutionReplace the shortcut logic with an explicit if.

if [[ -z "${http_client:-}" ]]; then
    http_get_client || return 1
fi

Files/functions likely affectedlibs/tools.sh: http_get; modules/weather.sh: weather_getinfo

Make Weather HTTP Calls Client-Safe

Must

ProblemThe emoji fetch calls http_get with a curl-specific -s flag.

Why it mattershttp_get is meant to hide the chosen client. Passing client-specific flags makes behavior fragile for wget, httpie, or fetch.

Suggested solutionPass only the URL to http_get, and include https://.

weather[emoji]="$(http_get "https://wttr.in/${location}?format=%c")"

Files/functions likely affectedmodules/weather.sh: weather_getinfo; libs/tools.sh: http_get

Stop Helper Functions From Exiting the Whole App

Should

ProblemShared helpers sometimes call exit 1 directly, including check_internet, required_commands, and run_module.

Why it mattersIn a launcher app, one module failure should usually return to the app cleanly instead of killing the whole session.

Suggested solutionPrefer return 1 in reusable helpers. Let top-level scripts decide whether to exit.

Files/functions likely affectedlibs/tools.sh: check_internet, required_commands, run_module; module callers

Make Bootstrap Error Handling Independent of Styles

Should

Problemtrap_error and log_error use style variables like ERROR, RESET, and ERRORTEXT, but bootstrap installs traps before styles are loaded.

Why it mattersIf an error happens early, strict mode can cause the error handler itself to fail because style variables are unset.

Suggested solutionEither load styles before installing traps, or make log_error tolerate missing style variables with defaults.

Files/functions likely affectedlibs/bootstrap.sh; libs/tools.sh: log_error, trap_error

Replace Global Parser Output With Safer Module Parsing

Should

Problemparse_module writes globals: module_name, module_question, and module_shortcuts.

Why it mattersThis is easy to break later. A future function can accidentally reuse or overwrite those globals.

Suggested solutionKeep it simple: document these globals clearly or rename them with a GM_PARSED_ prefix. Longer term, parse inside the loop using local variables.

Files/functions likely affectedlibs/tools.sh: parse_module; main.sh: list_questions, execute_shortcut

Harden Config Entry Validation

Should

ProblemGM_MODULES entries depend on pipe-delimited fields. There is no validation for malformed entries, empty script names, empty questions, or accidental | inside labels.

Why it mattersA small typo in config can produce confusing runtime behavior.

Suggested solutionExtend validate_modules or add validate_module_config to check minimum field count and non-empty fields.

Files/functions likely affectedconfig.sh; libs/tools.sh: parse_module, validate_modules, validate_shortcuts

Fix Backup Path Assumptions

Should

ProblemBackup excludes only ./${BACKUP_DIR##*/}. That works only when the backup directory is a direct child of the source directory and basename matching is enough.

Why it mattersIf BACKUP_DIR changes to a nested path inside DIR_TO_BACKUP, previous backups may be included recursively.

Suggested solutionValidate DIR_TO_BACKUP exists, resolve both paths, and exclude the backup path relative to the source when it is inside the source.

Files/functions likely affectedmodules/backup.sh; config.sh: DIR_TO_BACKUP, BACKUP_DIR

Clean Up Placeholder Crypto Module Behavior

Should

Problemcrypto is registered as a real module, but modules/crypto.sh only prints test text and sleeps.

Why it mattersFrom the launcher UX, it looks like a supported feature but behaves like a stub.

Suggested solutionEither remove it from GM_MODULES until ready, or make the module show a clear "not implemented yet" message and exit cleanly.

Files/functions likely affectedconfig.sh; modules/crypto.sh

Guard Terminal State Functions

Could

Problemhide_keyboard, show_keyboard, and clear assume an interactive terminal.

Why it mattersRunning scripts from non-interactive contexts, cron, redirected stdin, or tests can fail noisily.

Suggested solutionGuard terminal operations with [[ -t 0 ]] / [[ -t 1 ]], and tolerate missing TERM.

Files/functions likely affectedlibs/tools.sh: hide_keyboard, show_keyboard, clearscreen, flushread
